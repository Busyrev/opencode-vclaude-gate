# opencode-vclaude-gate

**Навайбкожено.** Написано агентом (opencode + claude-opus-5) по итогам
рисёча логов и реверса бинаря opencode 1.18.25. Тестами покрыто, на живом
API проверено, но человеком построчно не вычитано. Пользуйся с этим в уме.

## Настройка vclaude.ru

Для начала нужно указать vclaude.ru url в конфиге, вот так выглядит полный конфиг свежего сетапа opencode

`~/.config/opencode/opencode.jsonc` 

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "options": {
        "baseURL": "https://vclaude.ru/v1"
      }
    }
  }
}

```

Потом /connect в опенкоде и там выбираете anthropic любую модель, кроме fable 5.1 (на 2026-09-13 она не поддерживается шлюзом)  
Вводите ключ целиком с sk-vcl-...

## Установка плагина

opencode сканирует `{plugin,plugins}/*.{ts,js}` в каждой конфиг-директории,
включая глобальную, и ходит по симлинкам. Правки в `opencode.json(c)` не
нужны.

```sh
git clone https://github.com/Busyrev/opencode-vclaude-gate.git ~/opencode-vclaude-gate   # или просто скопируй папку
mkdir -p ~/.config/opencode/plugin
ln -s ~/opencode-vclaude-gate/plugin/vclaude-concurrency.ts \
      ~/.config/opencode/plugin/vclaude-concurrency.ts
```
Дальше **перезапусти opencode** — конфиг и плагины читаются один раз при
старте, горячей перезагрузки нет.


Плагин для [opencode](https://opencode.ai), который не даёт клиенту вылезти
за лимит одновременных запросов провайдера `vclaude.ru`.

## Зачем

`vclaude.ru` держит жёсткий лимит: **5 одновременных запросов на модель на
ключ**. Слот занят всю длительность стрима, шестой запрос получает HTTP 429
с безликим `{"message":"Сервис временно недоступен. Попробуйте позже."}` —
причина в теле не указана, и клиент не может отличить это от реальной
недоступности сервиса.

Для агентного клиента это ловушка: главный поток + три параллельных
субагента + генерация заголовка сессии = 5–6 стримов, из которых длинные
держат слоты минутами. Субагенты падают после нескольких ретраев.

Подробности рисёча лимитов: <https://gist.github.com/Busyrev/336dea31ba8473daedce5379430b68f3>

Встроенной настройки конкурентности у opencode нет — ни в
`https://opencode.ai/config.json`, ни среди переменных `OPENCODE_*`
(`OPENCODE_ENABLE_PARALLEL` — это про параллельные вызовы инструментов
внутри одного запроса, не про число стримов).

## Как работает

opencode пробрасывает пользовательскую функцию `fetch` из
`provider.<id>.options` прямо в SDK-провайдер (см. `Provider.getLanguage`:
`let {fetch: L, ...} = V; const M0 = L ?? fetch`). Плагин этим пользуется.

1. Хук `config` находит провайдера, у которого в `options.baseURL` есть
   `vclaude.ru`, и подменяет его `fetch` на обёртку с семафором. Остальные
   провайдеры не трогает. Прежний пользовательский `fetch`, если он был,
   вызывается внутри.
2. Имя модели достаётся из тела запроса регуляркой `"model":"..."` — без
   `JSON.parse`, потому что тела бывают по 600 КБ. Счётчик у каждой модели
   свой, как и лимит на стороне сервера.
3. Свободен слот — запрос идёт сразу. Нет — встаёт в FIFO-очередь и ждёт
   вместо того, чтобы словить 429. Если во время ожидания срабатывает
   `AbortSignal` запроса (Esc, таймаут), запрос уходит из очереди и слот
   не тратит.
4. Слот освобождается **по концу тела ответа, а не по заголовкам** — именно
   так его считает сервер. Тело оборачивается в свой `ReadableStream`,
   release дёргается на `done`, на `cancel()` и на ошибке чтения.
5. Страховка: слот, удерживаемый дольше 10 минут, принудительно
   возвращается в пул (сам запрос при этом не рвётся), в stdout падает
   предупреждение.

Гейт ловит **все** обращения к провайдеру: главный поток, субагентов,
генерацию заголовка сессии, суммаризацию и авто-компакцию.

## Настройки

| Переменная окружения      | По умолчанию | Что делает                                            |
| ------------------------- | ------------ | ----------------------------------------------------- |
| `VCLAUDE_MAX_CONCURRENCY` | `5`          | Сколько одновременных запросов разрешать на модель     |
| `VCLAUDE_GATE_DEBUG`      | не задана    | Логировать ожидания в очереди (по умолчанию плагин молчит, чтобы не сорить в вывод `opencode run`) |

Порог принудительного возврата слота — константа `HOLD_TIMEOUT_MS` в шапке
плагина.

Проверить, что плагин жив:

```sh
VCLAUDE_GATE_DEBUG=1 opencode run --model anthropic/claude-haiku-4-5 "верни ровно: ok"
# [vclaude-gate] провайдер anthropic: лимит 5 одновременных запросов на модель
```

## Тесты

Нужен [bun](https://bun.sh) (node без поддержки TypeScript не подойдёт):

```sh
bun test/vclaude-concurrency.test.mjs
```

Семь сценариев: пик конкурентности и порядок FIFO, удержание слота до конца
тела, `cancel()` тела, ошибка upstream, ответ без тела, abort ожидающего
запроса, независимость счётчиков по моделям. Тесты дёргают настоящий хук
`config` и работают с тем же `fetch`, который получает opencode, — внутренности
плагина наружу не торчат.

Живая проверка против API (два параллельных субагента при лимите 1):

```sh
VCLAUDE_GATE_DEBUG=1 VCLAUDE_MAX_CONCURRENCY=1 \
  opencode run --model anthropic/claude-haiku-4-5 \
  "Одним сообщением запусти ровно двух субагентов explore параллельно: каждому задача — просто вернуть слово ping."
# [vclaude-gate] claude-haiku-4-5: занято 1/1, встаю в очередь (1)
# [vclaude-gate] claude-haiku-4-5: ждал слот 1207 мс, в очереди ещё 0
```

## Ограничения

- **Счётчик живёт в процессе opencode-сервера.** Два одновременно запущенных
  инстанса opencode (разные проекты, разные окна) дадут 5 + 5 и снова упрутся
  в лимит. Для этого случая нужен отдельный локальный прокси-процесс — здесь
  такого нет.
- **Слот может утечь на 10 минут.** Если opencode бросит ответ, не дочитав
  и не отменив тело, слот вернётся только по страховочному таймеру. На
  реальных прогонах такого не наблюдалось, но случай возможен.
- **После принудительного возврата слота конкурентность может кратковременно
  превысить лимит** — плагин не рвёт зависший запрос, а просто перестаёт
  держать под него слот.
- **Лимит считается по модели из тела запроса.** Если тело придёт не строкой
  (Buffer, stream) или без поля `model`, запрос попадёт в общий бакет
  `unknown`. На текущем пути opencode тело всегда строка.
- **Ответ пересобирается** (`new Response(body, {status, statusText, headers})`),
  так что поля `url`, `redirected`, `type` теряются. AI SDK ими не
  пользуется, но сторонний код мог бы.
- **Завязано на внутренности opencode 1.18.x** — на то, что провайдерский
  `options.fetch` пробрасывается в SDK. Если это уберут в новой версии,
  плагин молча перестанет ограничивать. Проверяй debug-строку после
  обновлений.
- **Не решает вторую проблему vclaude** — маскировку превышения контекста под
  «Сервис временно недоступен». Тут поможет только фикс на стороне провайдера.
